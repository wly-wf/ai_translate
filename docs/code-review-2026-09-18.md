## 按优先级排序的问题

### 1. [P1] 默认重定向可能泄漏 Azure API Key，且绕过 HTTPS 限制

位置：`src-tauri/src/lib.rs:1419`、`:1787`、`:1851`。

`build_http_client` 未设置重定向策略，`authenticated_request` 对 Azure 路径使用自定义 `api-key` 请求头，URL 安全验证只针对最初地址。核对本地锁定版本 reqwest 0.13.4 源码可知：默认跟随重定向、`https_only` 默认关闭，跨域时清理 Authorization/Cookie 等头，但不清理 `api-key`。

触发条件：配置的 API/网关返回指向另一源的重定向；Azure 风格密钥会继续带到目标。307/308 还可能将包含原文的 POST 请求体转发，HTTPS 到 HTTP 重定向也未被本项目禁止。这里是已核对代码的条件性风险，不表示已经发生泄漏。

建议：API 默认不跟随重定向，或仅允许同源且不降级的跳转；增加使用虚拟密钥、本地服务器的跨源/降级回归测试。不能仅依靠最初 Base URL 校验。

### 2. [P1] 第二个自定义供应商会覆盖第一个

位置：`src/App.tsx:2291`、`:2368`；`src-tauri/src/lib.rs:1457`、`:2245`。

“添加接口”始终使用 `GENERIC_PROVIDERS[0]`，即 `openai`。存储键固定为 `provider-config:openai`。添加 A 后再添加 B，不会创建独立供应商，而是把 A 的名称、地址、密钥和模型覆盖掉，界面没有明确的替换提示或已有槽限制。

建议：供应商实例使用独立 ID，协议类型另设字段；若产品确实只支持一个自定义接口，就禁止重复添加并明确进入编辑。

### 3. [P2] 自动保存事件强制切页，并可能回写旧草稿

位置：`src/App.tsx:1634`、`:1855`；`src-tauri/src/lib.rs:2301`。

每次保存自定义配置都会发出 `provider-config-saved`。设置页把任何这种事件都当作“新增供应商”，重新读取配置、替换草稿、选择该供应商并执行 `setSettingsPage("generic")`。

已复现：用户在偏好页时收到 `openai` 保存事件，页面立刻跳回供应商。若自动保存返回时用户已继续输入，还可能被读取结果覆盖；此处没有草稿版本保护。

建议：区分创建事件与更新事件，更新事件只刷新必要元数据，不导航、不覆盖较新的本地编辑。

### 4. [P2] 删除最后一个模型不会持久化

位置：`src/App.tsx:1810`、`:1833`；`src-tauri/src/lib.rs:2257`。

移除模型后 UI 允许列表为空，但自动保存发现 `!models.length` 会直接返回。后端仍保留之前的模型及启用状态。重新读取会恢复旧模型，后续划词翻译仍可能调用用户以为已删除的模型。

已复现：移除唯一模型并等待超过 500 ms，没有调用保存或禁用命令。

建议：禁止删除最后一个模型并解释原因，或原子地持久化空列表并禁用该供应商。

### 5. [P2] 后台结果打断快速输入，并重置折叠状态

位置：`src/App.tsx:1015`、`:1093`。

`applyTranslationSnapshot` 在每次增量结果到达时都执行 `setShowQuickTranslate(false)` 和展开全部模型。用户等待慢模型期间打开快速翻译输入新文本，旧结果返回会立即把输入页关掉；已折叠的卡片也重新展开。文本 state 尚在，不是永久丢失，但当前操作被打断。

已复现后台结果关闭快速输入页。建议只在新批次开始时初始化视图；同一批次更新只更新结果。

### 6. [P2] 配置自动保存没有真正的写入顺序保障

位置：`src/App.tsx:1855`、`:1749`；`src-tauri/src/lib.rs:2291`、`:2351`。

前端请求编号只阻止旧响应更新界面，不会阻止已经发出的旧保存写入。后端每次独立 `spawn_blocking`，保存之间没有序列/版本校验。删除操作使用的锁也没有被保存操作共享。

触发条件：慢存储时连续编辑，或已有保存进行中时删除自定义供应商。可能出现旧配置最后写入，或删除后配置被进行中的保存重新创建。属于并发路径静态发现，未人为延迟真实凭据存储复现。

建议：以供应商实例为单位串行保存，删除与保存共享事务/版本约束；取消计时器不能替代取消进行中的写入。

### 7. [P2] “连接测试成功”没有证明模型返回有效响应

位置：`src-tauri/src/lib.rs:1896`。

测试仅判断 HTTP 成功状态，完全不验证响应体。200 HTML 登录页、空响应、兼容网关的 200 错误对象均会显示成功，实际翻译却无法解析；与界面“确认地址、密钥和模型都可用”的承诺不符。

建议：解析模型响应并检查有效文本/拒绝/错误结构；区分网络可达与模型可调用。

### 8. [P2] 配置读取失败会阻断所有供应商翻译

位置：`src-tauri/src/lib.rs:2117`。

建立目标列表时使用 `configured_provider(&provider)?`。只要一个已启用配置损坏或不可读，函数就提前返回，健康供应商也不会开始请求；请求发出后的错误处理则已经能按模型隔离。

建议：把配置错误同样放入对应供应商结果，继续启动其余有效目标；没有任何有效目标时再整体失败。

### 9. [P2] 旧批次不取消，模型数量也没有并发上限

位置：`src-tauri/src/lib.rs:2159`、`:1658`、`:2055`。

每个模型都 spawn 一个任务，每次请求又创建新的 HTTP Client。新翻译只替换 latest 状态，让旧结果不显示；旧网络请求依然执行，甚至继续发起一次纠正请求。连续划词翻译、多模型配置时会浪费请求额度、连接及内存，并增加限流概率。

建议：管理批次取消句柄、限制并发；复用按代理配置更新的 Client。已经发出的请求即使本地取消，也不能保证供应商不计费。

### 10. [P2] 凭据保存失败后，偏好开关仍显示新值

位置：`src/App.tsx:665`。

偏好先乐观更新，保存失败只删除 pending 标记并显示错误，没有恢复后端值。划词/置顶等开关可能显示已经改变，但原生行为仍是旧状态，直到另一次刷新。开机自启动已经采用保存成功后再确认状态的模式，其他偏好应保持一致。

建议：失败后回滚该版本对应的值，或重新读取权威状态，同时保留更新版本的编辑。

## 性能与资源管理

1. **每个代理输入字符都写存储。** `src/App.tsx:665`、`:2163` 将每次 onChange 排入保存链；`src-tauri/src/lib.rs:2549` 持有偏好互斥锁并写整个 JSON 到凭据管理器。键入一串地址会产生多次写入和全窗口广播，读取偏好的鼠标处理也可能等待同一把锁。建议文本字段防抖/失焦提交，合并更新，缩小锁范围。
2. **结果已有事件，仍每 150 ms 拉取完整快照。** `src/App.tsx:1136` 每秒约 6.7 次 IPC，每次克隆并序列化原文和全部结果，再 JSON.stringify 比较。长文本、多模型、慢请求时成本放大。建议事件为主、聚焦恢复快照，丢事件兜底低频退避。
3. **启动创建两个 WebView，悬浮按钮加载全部前端。** `src/main.tsx:4` 静态导入整个 App；`src-tauri/src/lib.rs:3097` 无论划词开关是否开启都创建悬浮 WebView。28 px 按钮也加载设置页、图标及全部样式。建议独立入口或按窗口拆包，关闭划词时考虑延迟创建相关资源。
4. **取词有明确等待成本。** `src-tauri/src/lib.rs:1021` 固定等待 120 ms；`windows_selection.rs:244` 每次启动辅助进程和两个读管道线程，2 秒超时且失败可重试一次。隔离进程确实能防止 UIA 卡死主程序，不应直接删除；应先测量后决定是否使用可重启常驻 helper。当前运行中的旧 capture 没有取消，因此卡住的旧目标可能延迟新选区。
5. **剪贴板快照只限制格式数，不限制总字节。** `windows_selection.rs:1114` 会复制各格式，包含大位图/富文本时可能造成明显瞬时内存和取词延迟。建议设置总字节/尺寸预算，超过预算放弃 Ctrl+C 兜底；强杀 helper 期间的恢复可靠性需实机压力验证。
6. **未发现单实例约束。** 入口及 Builder 没有单实例插件/进程互斥。重复启动会重复托盘、鼠标钩子、WebView，还可能让多个 Ctrl+C 兜底互相干扰。建议第二实例只激活已有实例。未进行多实例桌面实测。

## 代码风格与维护成本

- `src/App.tsx` 2441 行：四个窗口、偏好存储、供应商配置、事件状态、模型选择、图标和大量 JSX 集中在一个文件。SettingsWindow 单独接近千行，已形成明显耦合。建议按窗口组件、领域 hooks、IPC 类型、基础控件拆分。
- `src-tauri/src/lib.rs` 3226 行：网络协议、凭据管理、设置迁移、翻译调度、窗口布局、托盘、取词调度和大段测试混在一起。建议拆为 providers/config/translation/windows/tray 模块，保留 lib 作为组装入口。
- **确认存在不可达旧界面：** `renderConnectionPage`（`src/App.tsx:2067`）和 `connection` 页面分支仍保留，但没有把 settingsPage 设成 connection 的入口；连接测试已经放到供应商页。应清理该旧分支及专用样式。
- **兼容代码不等于废代码：** `save_api_key`、`get_active_provider`、`set_active_provider`、`has_api_key` 没有当前前端调用，但旧凭据迁移仍使用相关账户；先明确兼容范围，再删除无调用 IPC，不要直接删存储迁移逻辑。
- 前后端重复维护供应商 ID、默认模型、字号范围、版本号、IPC payload。建议建立统一契约，至少为字段和约束做边界测试。
- 多处 `.catch(() => undefined)` 静默忽略监听/配置加载失败；应区分允许失败的窗口外观操作与影响配置的错误，统一记录并反馈。
- TypeScript 已开启 strict/noUnusedLocals/noUnusedParameters，是正面基础；但 package.json 没有 lint/format 检查，Rust clippy 当前不可用。建议建立可重复的格式、静态检查和关键行为测试门禁。
- CSS 存在多次覆盖与旧页面样式，但不能仅凭重复选择器认定为废代码；应在拆分组件时结合实际 DOM 和视觉回归逐项清理。

## 已有的有效保护

5. 验收 Windows 真实划词、剪贴板、多 DPI、低分辨率固定窗口、代理、自启动、多实例；记录冷启动/空闲内存/连续划词延迟基线后再进一步优化。
